## 如何启动

推荐方式：双击项目根目录下的 `start-backend.bat`。

手动方式：

```bash
conda activate ai-interview-agent
cd backend
uvicorn app.main:app --reload
```

启动后打开：

- `http://127.0.0.1:8000/docs`
- `http://127.0.0.1:8000/`

## 本轮测试方式

后端接口可以用自动化测试。用户主要测试前端页面：

```bash
conda run -n ai-interview-agent python -m pytest backend/tests
```

1. 打开 `http://127.0.0.1:8000/`。
2. 点击“初始化题库”，看到顶部状态变为“题库已是最新”或“已新增 N 道题”。
3. 在“题库练习”中选择分类，点击“抽一道题”。
4. 查看下方“题库列表”，点击任意一题的“练这题”。
5. 在“新增题目”中添加一道题，确认它出现在列表并进入当前练习。
6. 在题库列表点击“编辑”，修改题目后保存。
7. 在题库列表点击“删除”，确认题目从列表消失。
8. 输入答案并点击“提交练习答案”，右侧应显示分数、反馈和参考答案。
9. 切换到“模拟面试”，选择题数，确认“本轮配置”显示正确。
10. 点击“开始面试”，连续回答到设置的题数后，右侧应显示最终报告。

## 正确结果

- 种子题库接口返回状态码 `200`，第一次响应中 `created` 大于 `0`。
- 第二次调用种子题库接口时，`created` 应为 `0`，说明不会重复导入。
- 初始化后题库应至少有 69 道，难度包含初级、中级、高级，并包含问答题、单选题和多选题。
- 查询题库列表返回状态码 `200`，能看到默认题目。
- 选择中级或高级后，题库列表和抽题仍应正常工作。
- 随机抽题返回状态码 `200`，响应中包含题目 `id`。
- 提交练习答案返回状态码 `200`，响应中包含 `score`、`feedback` 和 `standard_answer`。
- 提交练习答案响应应包含 `source`、`strengths`、`weaknesses`、`suggestions`。
- 创建模拟面试返回状态码 `201`，响应中包含 `session_id` 和 `current_question`。
- 提交面试答案返回状态码 `200`，未结束时包含 `next_question`，结束时 `is_finished` 为 `true`。
- 面试报告返回状态码 `200`，包含 `average_score` 和 `recommendation`。
- 前端页面可打开，无明显布局错乱。
- 顶部状态概览应显示筛选范围、当前练习和模拟面试状态。
- 切换分类或难度后，筛选范围和题库数量应同步变化。
- 难度下拉应显示初级、中级、高级。
- 抽题或点击“练这题”后，当前练习状态卡应显示题号和分类。
- 练习题应以卡片方式展示编号、分类、难度、题目和评分点。
- 答题框输入文字时，字数提示应实时变化。
- 题库列表能随分类和难度筛选变化。
- 点击“练这题”后，当前练习题应切换为列表中的题目。
- 新增题目后，列表刷新，当前练习题切换为新增题目。
- 编辑题目后，列表和当前练习题显示修改后的内容。
- 删除题目后，该题从列表中消失；如果当前正在练该题，练习区提示重新选择题目。
- 选中练习题和编辑题目时，题库列表中有明显高亮。
- 练习评分结果应分区展示，不是一整段混在一起。
- 练习评分结果应显示评分来源、优点、问题和建议。
- 提交练习答案后应立即出现“正在评分”的等待状态，最终再更新为完整评分结果。
- 抽到单选题时，应显示单选按钮选项；抽到多选题时，应显示复选框选项；选择答案后可直接提交。
- 模拟面试答题过程中，进度条应随答题推进。
- 每次面试回答应生成一张记录卡片。
- 面试记录顶部应显示当前平均分、已完成题数和阶段判断。
- 每题记录应显示分数等级和你的回答。
- 每题记录应显示评分来源、优点、问题和建议。
- 每题参考答案应可以折叠展开查看。
- 设置 1、2、3 或 5 题时，面试应按对应题数结束。
- 本轮配置应随顶部分类、难度和题数变化。
- 面试结束后应显示独立最终报告卡片。
- 最终报告应显示平均分、完成题数、完成状态、复习建议和下一步行动。
- 练习流程和模拟面试流程能在页面上完整跑通。
- 自动化测试应显示 `3 passed`。
