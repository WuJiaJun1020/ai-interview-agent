# AI Interview Agent 任务目标

## 当前总目标

持续开发 AI Interview Agent MVP，优先完成一个可演示、可测试、可迭代的 AI 面试练习系统。

当前阶段重点：

- 保持后端接口稳定可用。
- 尽快把前端体验打磨到可展示状态。
- 每次开发后维护 `AGENTS.md` 和 `docs/development-progress.md`。
- 维护一份长期任务目标，后续需求变化时允许按实际方向调整。
- 后续需求变化时，同步调整本文档。

## 当前产品范围

第一版 MVP 包含：

- 题库初始化。
- 种子题库覆盖 10 个常见后端面试分类，并包含初级、中级、高级难度。
- 题库练习：筛选分类/难度、抽题、提交答案、查看评分反馈和参考答案。
- 题库列表：查看当前筛选条件下的题目，并选择指定题目练习。
- 题目维护：在前端新增、编辑和删除题目。
- 模拟面试：开始面试、连续答题、查看每题反馈和最终报告。
- 面试配置：选择分类、难度和题数。
- 面试报告：展示每题得分等级、用户回答、参考答案、平均分、复习建议和下一步行动。
- 评分模式：默认 mock 规则评分；配置 API Key 后可切换到真实 LLM 评分。
- LLM 供应商：支持 OpenAI 兼容接口，当前本地优先验证阿里云百炼千问 `qwen3.7-plus`。
- 评分状态展示：前端能看到当前评分模式和 LLM 配置状态，但不暴露 API Key。
- 前端工作台：能清晰展示当前筛选、当前练习、面试进度和题目结构。

暂不优先做：

- 登录注册。
- 多用户权限。
- 复杂后台管理。
- 真实支付或部署。
- 过早引入复杂前端工程，除非当前静态页面明显不够用。

## 当前开发优先级

1. 先补齐后端自动化测试和发布检查清单，保证后续开发不容易回退。
2. 继续优化现有前端页面体验，让用户主要测试可视化交互。
3. 验证千问 3.7 Plus 真实评分效果，优化提示词和结构化输出。
4. 再考虑 RAG、LangGraph 和更完整的面试流程。
5. 优化项目说明、演示材料和版本标签。
6. MVP 稳定后打标签 `v0.1.0`。

## 质量要求

- 后端能自动测试的部分，由 Codex 自测通过后再交付。
- 用户主要测试前端页面和交互体验。
- 每次新增功能必须说明如何测试、什么结果算正确。
- 每轮开发可以比早期稍快，但仍要保持可测试、可回退、可解释。
- 不提交 `.env`、API Key、本地数据库和向量库文件。
- 文档使用中文，方便用户直接阅读。

如果后续用户改变方向，例如优先做前端、改技术栈、接入真实 LLM、调整项目展示目标，需要同步更新：

- `docs/task-goals.md`
- `AGENTS.md`
